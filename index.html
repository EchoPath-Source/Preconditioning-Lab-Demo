What the demo shows

Inspectable product behavior

  • route decisions become visible and comparable,
  • boundary and fallback state stay explicit,
  • Harp class can enrich repair semantics,
  • consumers see one source-agnostic bridge contract.

What it does not claim

Public-safe limits

  • kernel #12 is solved,
  • production runtime performance,
  • private kernel exposure,
  • public SDK or physics validation.

Boundary

Readable projection, protected source of truth

product consumer → kernel adapter / route-card → bridge event stream → overlay/debug UI. Product layers do not import private Preconditioning Lab research internals, Don source material, or private Q-RRG kernel internals.
